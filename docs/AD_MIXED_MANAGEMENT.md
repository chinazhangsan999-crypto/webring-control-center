# 第六阶段：广告混合管理

## 管理边界

总后台管理中央广告，各导航站可继续保留本地广告。中央广告支持全部站点、指定站点、指定分组或站点与分组的并集。定向模式至少选择一个目标，所有目标 ID 必须真实存在。

中央同步只替换 `managed_by='central'` 的广告，不删除或改写本地广告。中央广告、单站策略、当前修订号在一个 SQLite 短事务中落库；任何一项失败时整批回滚，站点继续使用上一份可用配置。

## 单站五广告位策略

`banner`、`icon`、`top_float`、`bottom_float`、`icon_float` 分别设置：

| 策略 | 执行方式 |
| --- | --- |
| `central_only` | 只展示命中本站的中央广告 |
| `central_first` | 中央广告先排序展示，随后是本地广告 |
| `mixed` | 中央与本地广告合并，按优先级从高到低稳定排序 |
| `local_only` | 只展示该导航站的本地广告 |

新建导航站默认五个广告位都是 `central_first`。修改策略时必须一次提交全部五个广告位，防止误操作造成部分策略丢失。

## 联盟代码

- 总后台以字符串原文保存 `ad_code`，不做 HTML 转义、过滤、压缩或重写。
- 快照携带 `integrity_sha256`，Agent 在落库前由共享协议校验内容完整性。
- 代码广告的平台固定为 `all`，由广告代码自身执行其平台判断。
- 总后台快照预览只显示元数据，不执行联盟代码。

## 优先级与稳定性

中央使用 `priority`，导航站本地广告使用 `sort_order`。混合选择器同时识别两个字段，数值越大越靠前；数值相同时保留原始顺序，避免每次刷新发生跳动。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/admin/ads` | 查询中央广告和投放目标 |
| `POST` | `/api/admin/ads` | 新增中央广告 |
| `PUT` | `/api/admin/ads/:id` | 修改内容、广告位、优先级、状态或范围 |
| `DELETE` | `/api/admin/ads/:id` | 删除中央广告 |
| `GET` | `/api/admin/ad-policies` | 查询所有站点的混合策略和同步状态 |
| `GET/PUT` | `/api/admin/sites/:id/ad-policies` | 查询或修改单站五广告位策略 |
| `GET` | `/api/admin/sites/:id/ads` | 预览单站下次会收到的中央广告快照 |

## 本阶段边界

本阶段只完成总后台、共享协议和 Agent 广告选择/落库适配代码。不部署到云端，不修改现网广告，不关闭各导航站的本地广告管理入口。
