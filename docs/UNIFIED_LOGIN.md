# 第四阶段：统一后台登录

## 最终流程

1. 超级管理员只在总后台输入一次账号和密码。
2. 在“导航站”中点击“进入后台”。前端同步打开一个空白页，避免异步请求完成后被浏览器拦截。
3. 总后台为目标站生成 60 秒一次性票据。新票据会撤销该管理员此前为同站生成但尚未使用的票据。
4. 浏览器进入目标站 `/api/admin/control-center/login#control-ticket=...`。票据位于 Fragment，不会进入目标站、反向代理或 CDN 的访问日志。
5. 目标站过渡页立即清除 Fragment，再把票据同源 POST 给 Agent。Agent 使用该站独立凭据，从服务器端向总后台兑换票据。票据绑定站点、只能使用一次，串站、重放或超时均失败。
6. 目标站签发自己的本地管理员令牌，并生成仅保存于该站内存、30 秒有效的一次性交换码。
7. 浏览器被重定向到 `/admin#control-sso=<交换码>`。片段不会发送到服务器；前端立即从地址栏清除片段。
8. 前端同源 POST 交换码，写入导航站现用的 `webring_admin_token`，随后恢复后台页面。

总后台票据和导航站交换码都不能直接作为长期后台令牌。最终后台权限仍由目标站使用自己的密钥签发，互不共享管理员密码和 JWT 密钥。

## 安全约束

- 总后台票据只保存 SHA-256 摘要，不保存明文。
- 总后台票据绑定唯一目标站，默认 60 秒失效且只能兑换一次。
- 总后台票据放在目标站地址的 Fragment 中，不进入 HTTP Referer、反向代理或访问日志。
- 同一管理员对同一站只保留最新的一张未使用票据。
- 导航站交换码只保存摘要，默认 30 秒失效且只能消费一次。
- 交换响应使用 `Cache-Control: no-store`、`Referrer-Policy: no-referrer` 和 `X-Content-Type-Options: nosniff`。
- 浏览器会拒绝跨站调用本地会话交换接口。
- 目标站 Agent 最多保留 500 个待交换请求，避免异常流量撑大内存。
- 总后台改密、回收其他会话、停用站点或轮换站点凭据时，会撤销对应未使用票据。
- 总后台和所有导航站必须使用 HTTPS；站点凭据、总后台 Session 密钥和各站 JWT 密钥必须分别保存。

## 导航站接入要求

每个导航站需要实现两项回调：

- `applyConfig(config)`：原子应用属于本站的节点、广告和发布页快照。
- `issueAdminToken(admin, context)`：使用本站 JWT 密钥签发管理员令牌；建议把 `context.nonce` 写入 JWT `jti`，并把来源写为 `control_center`。

后台前端启动时调用 `consumeControlCenterSso()`。默认写入现有键名 `webring_admin_token`，不会要求站长再次输入本站密码。

## 本地登录的阶段策略

第四阶段只建立统一登录闭环，不删除导航站原有登录接口。原入口作为灰度期应急通道，待至少一个测试站完成跨服务器、重放、过期、重启和回退验收后，再通过独立开关隐藏普通登录表单。隐藏表单不等于删除应急能力；最终应保留服务器端可审计的紧急恢复方式。

本阶段不读取、不修改、不验证任何现有导航站管理员密码，也不执行本地登录。
