# 第五阶段：统一节点管理

## 管理模型

节点只在总后台建立一份中央配置。超级管理员可以设置测速名称、展示名称、HTTP/HTTPS 地址、排序权重、启用状态和投放范围。投放范围支持：

- 全部启用站点；
- 一个或多个指定站点；
- 一个或多个站点分组；
- 指定站点与站点分组的并集，最终按节点 ID 去重。

定向模式至少选择一个站点或分组。保存前会确认所有目标真实存在，避免因错误 ID 生成无人接收的配置。

## 下发与一致性

1. 节点新增、修改、停用、删除或分组成员变化时，总后台增加 `nodes_revision`。
2. 各站 Agent 主动拉取自己的完整快照，不要求固定公网 IP，也不开放本站数据库。
3. 快照只包含启用并命中本站范围的节点，按 `sort_order DESC, id ASC` 稳定排序。
4. Agent 校验协议、站点归属、组合修订号、响应修订头和 ETag。
5. 导航站在一个 SQLite 短事务中只替换 `managed_by='central'` 的节点。
6. 全部落库成功后才更新本地修订号；失败时保留上一份可用快照。

总后台“已同步站点”通过站点心跳上报的 `applied_revision` 与目标 `nodes_revision` 比较。它表示该站已确认应用对应快照，不只是总后台完成保存。

## 本地数据边界

导航站节点表增加：

- `managed_by`：`local` 或 `central`；
- `central_id`：总后台节点 ID；
- `sort_order`：中央排序权重。

同步只删除旧中央节点，不删除本地节点。本地节点与中央节点 URL 冲突时，整次快照应用失败并回滚，不会静默覆盖或丢失任一侧数据。管理员解决冲突后，Agent 会在下一轮重新同步。

正式完成站点灰度接入后，可隐藏导航站原有“节点管理”和节点 CSV 同步入口，让总后台成为唯一写入口。在此之前不直接删除本地入口，便于故障回退。

## API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/admin/nodes` | 查询全部中央节点及投放目标 |
| `POST` | `/api/admin/nodes` | 新建中央节点 |
| `PUT` | `/api/admin/nodes/:id` | 修改节点、状态、排序或投放范围 |
| `DELETE` | `/api/admin/nodes/:id` | 删除节点 |
| `GET` | `/api/admin/sites/:id/nodes` | 预览某站实际会收到的节点快照 |
| `GET` | `/api/agent/config` | Agent 拉取包含节点的完整配置快照 |

所有管理员写入继续受总后台 Session、同源和 CSRF 保护，并把操作者、节点地址、状态、排序及投放范围写入审计日志。

## 本阶段边界

本阶段完成总后台、共享协议和 Agent 适配代码，不部署到云端，不登录现有导航站，也不关闭现网站点的本地节点入口。
