# 总后台后端设计

## 管理员模型

系统只允许一个超级管理员，不提供管理员列表、新增管理员、角色或权限分配 API。`admins.singleton_key` 是固定为 `TRUE` 的唯一列，数据库唯一索引保证任何路径都不能插入第二个账号。如果迁移前已有多个账号，迁移会明确中止，不会擅自删除管理员数据。

首次启动由 `INITIAL_ADMIN_USERNAME` 和至少 12 位的 `INITIAL_ADMIN_PASSWORD` 创建唯一账号。之后环境变量不会覆盖数据库中的用户名或密码。

## 认证与会话

- 登录只查询唯一账号，用户名错误时仍执行等成本 bcrypt 校验。
- 同一 IP 15 分钟内最多 8 次尝试，内存记录有数量上限和过期清理。
- Session 使用 `HttpOnly` + `SameSite=Strict` Cookie，生产环境开启 `Secure`。
- 所有后台写操作都需要 CSRF Token 和同源校验。
- 每个账号最多保留 5 个有效会话，并记录 IP、User-Agent、创建时间和最后活跃时间。
- 修改账号后自动注销其他会话、撤销未使用 SSO 票据并轮换当前 CSRF Token。
- 后台 API 统一返回 `Cache-Control: no-store`。

## 超级管理员 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/auth/login` | 登录唯一超级管理员 |
| `GET` | `/api/auth/me` | 读取当前账号与 CSRF Token |
| `POST` | `/api/auth/logout` | 注销当前会话 |
| `GET` | `/api/admin/security` | 查看账号与有效会话 |
| `PUT` | `/api/admin/security/account` | 验证当前密码后修改用户名/密码 |
| `POST` | `/api/admin/security/revoke-sessions` | 保留当前会话并注销其他会话 |

## 业务 API

- 站点：登记、编辑、启停、站点凭据轮换、一次性 SSO 入口。
- 分组：创建、编辑、删除及成员关系管理。
- 节点：全局、指定站点或指定分组的增删改查、排序、有效快照预览与同步状态。
- 广告：普通广告与联盟代码广告的完整管理，代码原文保存。
- 广告策略：每个站点、每个广告位独立决定中央与本地广告的关系。
- 发布页：每站配置、生成任务和任务去重。
- 任务：最近 100 条查询、失败任务重试、未开始任务取消。
- 审计：记录登录、退出、账号变更、会话回收与业务写操作。

## 一致性与运行

- 配置写入、分项修订号更新和审计日志处于同一 PostgreSQL 事务。
- 同一站点同时只允许一个活跃发布任务；重复点击返回已有任务。
- 任务执行器使用 `FOR UPDATE SKIP LOCKED`，支持多实例安全抢占。
- 进程退出时等待当前任务收口，再关闭 HTTP 和数据库连接。
- `/api/health` 是存活检查；`/api/ready` 会实际查询 PostgreSQL，用于反向代理或容器就绪检查。

## 第三阶段边界

本阶段完成后端与单账号安全边界，不执行云端部署、GitHub 提交、现网数据迁移或导航站 Agent 接入。

## 管理界面

总后台参照现有导航系统管理中心的布局语言：顶部品牌区、横向胶囊标签、浅色背景和白色圆角内容卡片。只复用视觉结构，不加载旧后台脚本；认证、数据读取和写入全部调用总后台 API。窄屏使用横向滚动标签，表格保留独立横向滚动，避免压缩字段。
