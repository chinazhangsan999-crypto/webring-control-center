# 第九阶段：总后台发布页管理

## 目标

总后台以站点为单位管理永久发布页。管理员可以在一个页面内确认配置是否完整、当前内容是否已发布、Cloudflare 和 GitHub 是否分别成功，并完成预览、发布、查历史和失败重试。

## 管理界面

顶部统计：

- 站点总数；
- 已完整配置数；
- 已是最新数；
- 待发布或正在发布数；
- 最近发布失败数。

每个站点展示：

- 站点名称与站点标识；
- 当前发布修订号和节点修订号；
- 自定义永久域名和 GitHub Pages 地址，均可打开或复制；
- Cloudflare 与 GitHub 的独立发布状态；
- 最近发布时间和失败原因；
- 预览、发布历史、配置页面、重试失败平台和发布到双平台操作。

## 状态口径

- `配置未完成`：缺少两个发布地址、GitHub 仓库或 Cloudflare 项目中的至少一项。
- `等待发布` / `正在发布`：该站已有一个未完成任务，不允许再创建第二个同类任务。
- `发布失败`：最近一个任务最终失败，界面直接展示原因和重试入口。
- `已是最新`：最近任务成功，且其构建中的发布修订号、节点修订号都与当前站点一致。
- `有更新待发布`：没有成功发布记录，或发布页/节点在上次成功后发生过变化。

## 预览

`GET /api/admin/sites/:id/publish/preview` 使用当前已保存配置和当前有效节点，在内存中生成与正式发布相同的 HTML。该接口：

- 需要超级管理员登录；
- 只读，不创建任务；
- 不写本地发布目录；
- 不请求 Cloudflare 或 GitHub；
- 返回 `Cache-Control: no-store`。

## 发布历史

`GET /api/admin/sites/:id/publish/history` 返回该站最近 20 条 `publish.deploy` 任务，包含任务状态、双平台结果、内容摘要、尝试次数、时间和失败原因。失败任务可以复用现有重试接口。

重试保留第八阶段规则：如果页面和节点修订号没有改变，已成功平台不重复发布，只重试失败平台；如果修订号已变，则两个平台都发布最新内容。

## 边界

- 本阶段不自动创建 DNS 记录；
- 不删除远端仓库、Cloudflare 项目或历史任务；
- 不新增数据库表，历史直接使用已有持久化任务队列；
- 不改变双平台凭据来源、权限和远端摘要验收规则。
